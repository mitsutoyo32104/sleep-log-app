# Sleep Log App

睡眠記録を紙媒体で管理していた課題を解決するために開発している、個人用の睡眠記録Webアプリです。

## 開発の背景

これまで睡眠時間・体調・気分などを紙の日誌に記録していましたが、

- 入力の手間がかかる
- 過去の記録を振り返りにくい
- 周囲(支援者・家族等)と記録を共有しにくい

という課題があり、Webアプリとしていつでも入力・確認できる仕組みを作ることにしました。

## アーキテクチャ

フレームワークを使わず、MVC(Model-View-Controller)にRepositoryパターンを組み合わせた構成で設計しています。`.htaccess` によるフロントコントローラーパターンで全リクエストを `index.php` に集約し、`route.php` で定義したルーティングから各Controllerへ処理を振り分けています。ModelとDB操作の間には Repository層を挟み、データアクセス処理を分離しています。

### ディレクトリ構成

```
sleep-log-app/
├── controllers/   # リクエストの処理・Model呼び出し
├── models/        # データの構造定義（後からvalidationルールの定義予定）
├── repositories/  # DBアクセス処理(Modelから分離)
├── views/         # 画面表示(テンプレート)
├── partials/      # 共通パーツ(ヘッダー・フッター等)
├── css/           # スタイル(Sassコンパイル後)
├── js/            # クライアントサイドの処理
├── libs/          # 共通ライブラリ・ヘルパー関数
├── sql/           # テーブル定義(DDL)
├── config.php     # 設定ファイル
├── route.php      # ルーティング定義
├── index.php      # フロントコントローラー
└── .htaccess      # URL書き換えルール
└── .env.php      # DB情報ファイル

```

## 設計・実装で工夫した点

### 1. Repositoryパターンによるデータアクセスの分離

`models/` にデータの構造を、`repositories/` にDBへのアクセス処理を分けて置くことで、
「データの扱い方」と「データの取得方法(SQL)」の責務を分離しています。

### 2. パスワードの安全な保存

パスワードは平文・暗号化ではなく、`password_hash()` によるハッシュ化(bcrypt)で保存し、
ログイン時は `password_verify()` で照合しています。ハッシュ化は不可逆な処理のため、
サーバー側であっても元のパスワードを復元できない設計です。

### 3. 退会機能は論理削除(ソフトデリート)で実装

退会処理は、レコードを物理的に `DELETE` するのではなく、`del_flg` カラムを `1` に更新する
論理削除方式にしています。誤操作や不正な削除リクエストで大切なデータが消えてしまうリスクを避け、
必要であれば後からデータを復元・調査できるようにするための設計判断です。
